Installing shipit

Get from zero to your first deploy in about five minutes.

shipit is a single-binary command-line tool that builds, tags and deploys your app to any SSH host or container registry. This page walks through installing it, wiring it into a project, and the flags you will use most.

Requirements

  • macOS 12+, Linux (glibc 2.31+ or musl), or Windows 10+ with WSL2
  • Git 2.30 or newer
  • Docker 24+ if you deploy containers (optional for SSH-only targets)

Install shipit

  1. Install the binary with your package manager, or with the install script:

    # macOS
brew install shipit

# Debian / Ubuntu
curl -fsSL https://get.shipit.dev/apt.gpg | sudo gpg --dearmor -o /usr/share/keyrings/shipit.gpg
echo "deb [signed-by=/usr/share/keyrings/shipit.gpg] https://apt.shipit.dev stable main" | sudo tee /etc/apt/sources.list.d/shipit.list
sudo apt update && sudo apt install shipit

# Anything else
curl -fsSL https://get.shipit.dev | sh

  2. Check that it is on your PATH:

    $ shipit --version
shipit 3.4.1 (linux/amd64, built 2026-10-14)

  3. Log in once so shipit can read your deploy targets:

    shipit login

    This opens a browser window. On a headless server, use shipit login --device and enter the code it prints.

Warning: Do not run the install script with sudo sh. The script asks for elevated rights only for the final copy into /usr/local/bin; running the whole thing as root writes your config to /root/.config/shipit, where your normal user cannot read it.

Configure your project

Run shipit init in the root of your repository. It writes a shipit.toml like this one:

[app]
name = "storefront"
build = "npm ci && npm run build"

[targets.production]
host = "deploy@prod-1.example.com"
path = "/srv/storefront"
health_check = "https://storefront.example.com/healthz"

[targets.staging]
host = "deploy@staging.example.com"
path = "/srv/storefront"

Then deploy to staging:

shipit deploy staging

Keyboard shortcuts

While shipit deploy is running in an interactive terminal:

Keys Action
l Toggle the live log view
p Pause after the current host finishes
r Retry the hosts that failed
Ctrl + C Stop and roll back hosts already deployed
Ctrl + \ Stop immediately without rolling back

FAQ

Does shipit need an agent on my servers?

No. shipit connects over SSH with your existing keys and only needs tar and a POSIX shell on the remote host.

How do I roll back a bad release?

Run shipit rollback production. shipit keeps the last five releases on each host and switches the current symlink back to the previous one.

Can I use shipit in GitHub Actions?

Yes. Install it with the script above, set SHIPIT_TOKEN as a repository secret, and run shipit deploy production --yes.

Where is my configuration stored?

Project settings live in shipit.toml. Your login token lives in ~/.config/shipit/credentials on macOS and Linux, and in %APPDATA%\shipit on Windows.

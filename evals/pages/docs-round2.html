Getting started with shipit

Install the CLI, connect a project, and ship your first release in under five minutes.

shipit is a single-binary command-line tool that builds your project, uploads the artifacts, and promotes the release through your environments. It works with any language that produces files on disk and needs nothing installed on your servers beyond SSH.

Installation

shipit runs on macOS, Linux, and Windows (via WSL2). Pick one of the methods below.

1. Install the binary

With Homebrew on macOS or Linux:

brew install shipit-cli/tap/shipit

Or with the install script, which places the binary in ~/.local/bin:

curl -fsSL https://get.shipit.dev/install.sh | sh

Or with npm, if you already have Node.js 18 or newer:

npm install --global @shipit/cli

2. Check the installation

$ shipit --version
shipit 2.4.1 (darwin/arm64, built 2026-10-14)

3. Log in

Authenticate once per machine. This opens your browser and stores a token in ~/.config/shipit/credentials.

shipit login

Warning: shipit deploy --force skips the health check and replaces the running release immediately. If the new build fails to start, your service will be down until you run shipit rollback. Never use --force on production from CI.

Your first deploy

From the root of your project, create a config file and deploy to the default staging environment:

shipit init
shipit deploy

shipit init writes a shipit.toml like this one:

[project]
name = "acme-web"
build = "npm run build"
output = "dist/"

[env.staging]
hosts = ["staging-1.acme.internal"]

[env.production]
hosts = ["web-1.acme.internal", "web-2.acme.internal"]
require_approval = true

When the staging release looks good, promote it:

shipit promote staging production

FAQ

Does shipit need an agent running on my servers?

No. shipit connects over SSH using your existing keys, uploads the release to /srv/<project>/releases/, and switches a symlink. Nothing stays running on the host.

How do I roll back a bad release?

Run shipit rollback --env production. It points the symlink back to the previous release, which takes a few seconds because the old files are still on disk. shipit keeps the last five releases by default.

Can I use shipit from GitHub Actions?

Yes. Create a token with shipit tokens create --scope deploy, store it as the SHIPIT_TOKEN secret, and add shipit deploy --env staging --quiet as a step. See Continuous integration.

Where are logs stored?

Each deploy writes a log to ~/.local/state/shipit/logs/. Run shipit logs --last to open the most recent one.
